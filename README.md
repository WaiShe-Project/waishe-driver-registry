# waishe-driver-registry

WaiShe 的驱动索引：记录哪些设备由哪个驱动支持、驱动的版本与下载信息，以及每项功能的验证情况。

**当前阶段：规划。尚无索引数据。** 在线安装流程计划在 M2 交付；在此之前驱动通过本地旁加载安装。

## 它是什么，不是什么

| 是 | 不是 |
| --- | --- |
| 一份经过签名的静态索引 | 需要账号的应用商店 |
| 设备兼容表与验证记录的来源 | 会接触用户硬件的服务 |
| 驱动版本、哈希与下载地址的登记处 | 驱动源码的存放处，源码在各驱动自己的仓库 |

Bridge 把整份索引下载到本地再做匹配。Registry 不提供按设备查询的接口，因此不会得知任何用户拥有哪些设备。

## 信任层级

| 层级 | 含义 | Bridge 的处理 |
| --- | --- | --- |
| `official` | WaiShe 组织维护的驱动 | 用户确认后安装 |
| `community` | 第三方维护，已通过收录检查 | 用户确认后安装，界面标明为社区驱动 |
| `local` | 未经 Registry，用户从本地文件安装 | 需开启开发者模式，界面持续标明 |

收录不等于担保。收录检查能确认的是来源、许可证、清单合规和基本的安全规则，不能确认驱动在每台设备上都工作正常。后者由验证等级表达。

## 验证等级

按 设备 × 连接方式 × 能力 记录：

| 等级 | 含义 | 必需的证据 |
| --- | --- | --- |
| `verified` | 实机验证通过 | 固件版本、连接方式、验证日期、验证人 |
| `simulated` | 回放测试通过，未经实机 | 随驱动仓库提交的回放用例 |
| `inferred` | 与已验证型号属于同一协议族，推断可用 | 说明依据的型号 |
| `broken` | 已知不可用 | 问题链接 |

## 收录流程

1. 驱动在自己的仓库发布一个版本，产出驱动包。
2. 向本仓库提交 PR，新增或更新该驱动的条目。
3. 自动检查：清单格式、接口版本、SPDX 许可证标识、下载地址可达、哈希一致、设备表与条目一致。
4. 人工审核：见下方条件。
5. 合并后重新生成并签名索引。

### 收录条件

- 源码公开，许可证为 OSI 认可的开源许可证。
- 仓库含 `PROVENANCE.md`，写命令均有出处。
- 不包含固件升级、引导加载程序、出厂校准类命令。
- 驱动包可由公开源码复现构建。
- 验证等级如实填写；标为 `verified` 的条目附有证据。
- 匹配规则不过度宽泛：不得仅凭厂商 ID 匹配整个品牌而没有探测逻辑。

### 撤销

发现某个驱动版本有害或严重损坏时，在索引中把该版本标记为已撤销。Bridge 更新索引后拒绝加载被撤销的版本，并回滚到上一个未撤销的版本或停用该驱动。
